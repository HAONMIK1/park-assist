# 설계 결정 기록 (ADR)

되돌리기 어렵거나 나중에 "왜 이렇게 했지?"가 될 결정을 여기에 기록한다.

## 언제 쓰나

- 다른 선택지가 분명히 있었고, 그중 하나를 골랐을 때
- 나중에 누군가 "이거 이상한데?" 하고 되돌리려 할 만한 제약을 넣었을 때
- 안전·규격·호환성 때문에 편의를 포기했을 때

라이브러리 버전 올리기, 변수 이름 바꾸기 같은 일상적인 변경은 기록하지 않는다.

## 작성 규칙

- 파일명: `NNNN-짧은-제목.md` (예: `0003-battery-reporting.md`), 번호는 4자리 순번
- 한 번 머지된 ADR의 내용은 고치지 않는다. 결정이 바뀌면 **새 ADR을 쓰고**, 옛
  ADR의 상태를 `대체됨 (→ NNNN)`으로 바꾼다.

## 템플릿

```markdown
# NNNN. 제목

- 상태: 채택됨 | 대체됨 (→ NNNN) | 폐기됨
- 날짜: YYYY-MM-DD

## 맥락

어떤 상황이었고 무엇이 문제였는지.

## 결정

무엇을 하기로 했는지. 단정형으로.

## 결과

이 결정 때문에 무엇이 쉬워지고 무엇이 어려워지는지. 지켜야 할 제약.

## 검토한 대안

왜 다른 선택지를 버렸는지.
```
