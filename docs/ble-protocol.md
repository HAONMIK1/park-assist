# BLE 통신 규격

park-assist 기기(ESP32)와 안드로이드 앱 사이의 BLE 규격이다.
**이 문서가 규격의 단일 진실 공급원(single source of truth)이다.**
펌웨어와 앱 중 어느 쪽이든 이 문서와 다르게 동작하면 그쪽이 버그다.

규격을 변경할 때는 **이 문서 → 펌웨어 → 앱** 순서로 같은 PR에서 함께 고친다.

## 1. GATT 프로파일

| 항목 | 값 |
| --- | --- |
| 광고 기기 이름 | `PARK-01` |
| Service UUID | `6E400001-B5A3-F393-E0A9-E50E24DCCA9E` |
| TX 캐릭터리스틱 (notify, 기기 → 폰) | `6E400003-B5A3-F393-E0A9-E50E24DCCA9E` |
| RX 캐릭터리스틱 (write, 폰 → 기기) | `6E400002-B5A3-F393-E0A9-E50E24DCCA9E` |

Nordic UART Service(NUS)와 같은 UUID 체계를 쓰지만, 스트림이 아니라 **고정 길이
바이너리 패킷**을 주고받는다.

TX/RX 이름은 **기기 관점**이다. 앱은 TX를 구독(notify)하고 RX에 write한다.

### CCCD

TX 캐릭터리스틱의 notify를 켜려면 CCCD 디스크립터
`00002902-0000-1000-8000-00805F9B34FB`에 `ENABLE_NOTIFICATION_VALUE`(`0x01 0x00`)를
write해야 한다. `setCharacteristicNotification()` 호출만으로는 알림이 오지 않는다.

## 2. 체크섬

모든 패킷의 **마지막 바이트는 XOR 체크섬**이다.

```
XOR = 마지막 바이트를 제외한 전체 바이트를 순서대로 XOR
```

```c
uint8_t checksum(const uint8_t *p, size_t len) {  // len = 체크섬 제외 길이
    uint8_t x = 0;
    for (size_t i = 0; i < len; i++) x ^= p[i];
    return x;
}
```

수신 측은 **검증에 실패한 패킷을 조용히 버린다.** 일부 바이트만 반영하는 부분 갱신은
금지한다. 길이가 규격과 다른 패킷도 마찬가지로 버린다.

## 3. 수신 패킷 (기기 → 폰, notify)

### 3.1 거리 측정값 — 6바이트, 10Hz

```
[0xAA][d1][d2][d3][d4][XOR]
```

| 바이트 | 이름 | 설명 |
| --- | --- | --- |
| 0 | `0xAA` | 패킷 타입 (거리 측정값) |
| 1 | `d1` | CH1 거리 (cm) |
| 2 | `d2` | CH2 거리 (cm) |
| 3 | `d3` | CH3 거리 (cm) |
| 4 | `d4` | CH4 거리 (cm) |
| 5 | `XOR` | `0xAA ^ d1 ^ d2 ^ d3 ^ d4` |

- 전송 주기: **초당 10회 (100ms)**
- 거리 단위: **cm**, 부호 없는 1바이트
- **`0xFF` = 측정 실패 또는 미연결 센서.** 거리 255cm가 아니다. 유효 거리로 취급하거나
  최소값 계산에 넣으면 안 된다.
- 따라서 표현 가능한 유효 거리는 **0 ~ 254cm**다. 그보다 먼 거리는 254로 클램프한다.

### 3.2 채널 ↔ 물리 배치

`d1`=CH1 … `d4`=CH4이며, 차량 뒤에서 봤을 때 **좌 → 우** 순서다.
앱의 호(arc) 4개도 같은 순서로 그린다.

> ⚠️ 실제 장착 시 좌우가 뒤집혔는지 반드시 실측으로 확인할 것. 뒤집혔다면
> **펌웨어에서** 바로잡고 앱은 건드리지 않는다.

## 4. 송신 패킷 (폰 → 기기, write)

### 4.1 거리 기준 변경 — 5바이트

```
[0xBB][near][mid][far][XOR]
```

| 바이트 | 이름 | 설명 |
| --- | --- | --- |
| 0 | `0xBB` | 패킷 타입 (거리 기준 변경) |
| 1 | `near` | 위험 기준 (cm) — 이 값 이내면 위험 |
| 2 | `mid` | 경고 기준 (cm) |
| 3 | `far` | 주의 기준 (cm) |
| 4 | `XOR` | `0xBB ^ near ^ mid ^ far` |

- 제약: `near < mid < far`, 각 값은 1 ~ 254.
- 기본값: `near=30`, `mid=60`, `far=120`.
- 이 값은 **기기의 부저 경보 단계**를 바꾼다. 앱의 색 구간도 같은 값을 쓴다.
- 기기는 값을 비휘발성 메모리에 저장해 재부팅 후에도 유지한다.

### 4.2 전원 제어 — 3바이트

```
[0xCC][mode][XOR]
```

| 바이트 | 이름 | 설명 |
| --- | --- | --- |
| 0 | `0xCC` | 패킷 타입 (전원 제어) |
| 1 | `mode` | `0x00` = 대기, `0x01` = 작동 |
| 2 | `XOR` | `0xCC ^ mode` |

- **대기(`0x00`)**: 센서 발사와 부저를 멈춘다. BLE 연결은 유지한다.
- **작동(`0x01`)**: 정상 측정/경보를 재개한다.
- 기기는 이 값도 비휘발성 메모리에 저장한다. 부팅 시 기본값은 **작동(`0x01`)** 이다.
  (원칙 1: 폰이 없어도 동작해야 하므로 기본이 꺼짐이면 안 된다.)

## 5. 예시

거리 기준을 위험 25 / 경고 50 / 주의 100으로 바꾸는 패킷:

```
0xBB ^ 25 ^ 50 ^ 100
= 0xBB ^ 0x19 ^ 0x32 ^ 0x64
= 0xF4

→ BB 19 32 64 F4
```

CH1=45cm, CH2=120cm, CH3=측정실패, CH4=200cm인 측정값 패킷:

```
0xAA ^ 45 ^ 120 ^ 0xFF ^ 200
= 0xAA ^ 0x2D ^ 0x78 ^ 0xFF ^ 0xC8
= 0xC8

→ AA 2D 78 FF C8 C8
```

## 6. 타이밍과 연결 파라미터

- 측정값 패킷은 100ms 주기. 앱은 **1초 이상 패킷이 끊기면 "신호 없음"** 으로 본다
  (연결 자체가 끊긴 것과는 구분한다).
- 4채널을 순차 발사하므로 채널당 슬롯은 25ms다. 에코 타임아웃은 20ms(≈340cm)로 잡아
  슬롯 안에 들어오게 한다.
- MTU 협상은 필요 없다. 모든 패킷이 기본 ATT payload(20바이트) 안에 들어간다.

## 7. 미확정 / 확인 필요

아래 항목은 아직 규격에 없다. 구현하기 전에 결정해서 이 문서에 반영한다.

- [ ] **배터리 잔량.** 앱 메인 화면에 배터리 표시가 요구되었지만 `0xAA` 패킷에는
      배터리 필드가 없다. 후보:
      (a) 표준 Battery Service `0x180F` / 캐릭터리스틱 `0x2A19` (1바이트 %) — 규격을
      건드리지 않으므로 **이쪽을 권장**,
      (b) 새 상태 패킷 타입(예: `0xAD`)을 저주기로 notify.
      결정 전까지 앱은 배터리를 "알 수 없음"으로 표시한다.
- [ ] **명령 ACK.** 현재 `0xBB` / `0xCC`에 대한 응답이 없다. 앱은 write 성공
      (`onCharacteristicWrite`)만으로 반영된 것으로 간주한다. 기기가 값을 거부했을 때
      앱이 알 방법이 없다.
- [ ] **현재 설정값 조회.** 앱을 새로 깔거나 다른 폰에서 붙었을 때 기기에 저장된
      거리 기준을 읽어올 방법이 없다. 앱은 로컬에 저장된 값을 표시한다.
